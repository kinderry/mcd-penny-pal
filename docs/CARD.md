# 战报卡片：设计与踩坑记录

> 简报是「用起来」的，卡片是「截图发出去」的。
>
> 这个比赛的记分板是 GitHub Star，而 Star 来自"看着有意思"。
> 一份排版整齐的表格简报没人会转发；一张有情绪、有具体数字的卡片会。
> 所以卡片不是简报的附属品，它是一条独立的传播链路——也因此值得单独做、单独测。
>
> 卡片上的字是麦小省的声音（软软的、短短的、爱"哎呀哎呀"）；
> 这份文档是给要改代码的人看的，语气收着写，规格与口径一律保持精确。

---

## 一、规格

| 项 | 值 | 理由 |
|---|---|---|
| 尺寸 | 1080 × 1440 | 3:4 竖版，主流社交平台推荐比例 |
| 高度 | **自适应**（`min-height: 1440`） | 券多时内容会更长，写死高度会裁掉最后一行 |
| 形式 | 单文件 HTML + PNG | HTML 自包含（形象 base64 内联），PNG 可直接发 |
| 依赖 | 引擎零依赖；出 PNG 需要 Chrome/Edge + PIL | 见下方「降级路径」 |

产出命令：

```bash
python tools/run_card.py            # 离线，零 Token，读 fixtures/raw 的真实返回
python tools/run_card.py --live     # 实时直连 mcp.mcd.cn（需 MCD_MCP_TOKEN）
python tools/run_card.py --no-png   # 只出 HTML
```

## 三、三条卡片专属纪律

卡片会被截图转发，写错一个数字就是错在几十上百人眼前。所以卡片的纪律比简报更严：

1. **只讲能核到价的券。** 门店券里没有的券，卡片上一个数字都不给。
   拿券面价冒充实省额，是最容易发生也最恶劣的一种。
2. **部分可估时不说「今天能省」。** 改说「这是已核价的 2 张」，
   并在旁边点明还有几张没核过。把 2 张的金额说成 6 张的，就是撒谎。
3. **大数字只算最紧急那一组**（今天到期优先，没有才退到 T-3）。
   把 today + soon 混着算，屏幕上就会出现「2 张今天到期」配「4 条清单」的错位。

这三条都有自测断言守着（`tools/test_card.py`，30 项）。

## 四、踩坑记录（四个真实 bug，都不是猜的）

### 坑 1 · CSS 花括号撞上 `str.format`，尺寸静默失效

HTML 模板用 `str.format()` 填占位符，但 CSS 里全是 `{}`。第一版直接
`_TEMPLATE.format(...)` 当场抛 `KeyError: ' margin'`。

改成"先把 `<style>` 段的 `{}` 双写再 format"。但这个修法带来了更隐蔽的问题：
**样式段里的 `{w}` 也被双写成 `{{w}}`，format 只会把它还原成字面的 `{w}`**——
于是 `width: {w}px` 和 `min-height: {h}px` 变成浏览器看不懂的无效声明，
整条尺寸规则**静默失效**，卡片尺寸悄悄退化成由截图视口决定。

表现是：改了间距却完全不影响出图结果，怎么调都一样。

修法：**顺序必须是「先落地样式段里的占位符 → 再转义花括号 → 最后 format 正文占位符」。**

### 坑 2 · 固定画布高度，把最后一行挤出画面

画布写死 `height: 1440px`，券多时内容超过 1440，footer 最后一行
（仓库地址）被 `overflow: hidden` 裁掉——而且是**整行消失**，不是裁一半，
所以肉眼第一眼看不出来。

修法：高度改成 `min-height`，让卡片按内容自然撑开；
截图用一个足够高的视口（2400px），截完再按实际内容裁到
`max(1440, 内容底 + 1)`。这样内容少就是标准的 3:4，
内容多就顺延加高，任何数据量都不会被裁。

顺带一个教训：一开始靠肉眼估"底部还空多少"，调了三轮都调错方向。
**改用像素扫描测出内容底边（与画布外背景色比对），一次就对了。**

### 坑 3 · 大数字口径错位

大数字取的是 `d.urgent`（今日到期 + T-3）的合计，而大字结论取的是
"今天到期的张数"。于是同一张卡上出现：

```
今晚 23:59 就作废
你手上的 6 张券里，有 2 张今天到期     ← 说 2 张
¥19.6 这是已核价的 2 张               ← 却算了 5 张里的 2 张
中薯条买一送一 / 王牌小食拼 / 巧克力松饼 / 麦旋风   ← 列了 4 条
```

数字之间互相矛盾，但每一条单独看都"没错"——这是最难自查的一类 bug。

修法：汇总范围改成 `d.today or d.soon`，只算最紧急那一组；
T-3 的券用一行带过（"另外还有 3 张券在倒计时"），不铺开成清单。

### 坑 4 · 合规检查在整份 HTML 上做，被 base64 骗了

合规断言原本扫整份 HTML 找竞品名，结果扫出 `KFC`——来自内联形象图的
base64 数据，随机字符里凑出了这三个字母。

修法：**合规检查一律在纯文本上做**（`card_plain_text()` 剥掉标签，
但更重要的是必须排除 base64 那段）。这条也提醒了整个项目：
自测里凡是"扫关键词"的断言，都必须明确扫的是什么范围。

## 五、降级路径

卡片不是"条件完美才能出"，缺什么都能降级：

| 缺什么 | 行为 |
|---|---|
| 形象图 | 用一个「省」字占位圆，不影响出图 |
| PIL | 跳过内容裁切，按标准 1080×1440 视口截 |
| Chrome / Edge | 不出 PNG，仍生成自包含 HTML，浏览器打开手动截图 |
| 门店券（无估值） | 不显示任何金额，退化为"临期提醒卡" |
| 券包全空 | 神态切「空手」，正常出卡 |

自测覆盖了其中四条。

## 六、怎么验证

```bash
python tools/test_card.py      # 30 项：口径 / 溯源 / 回归 / 合规
python tools/test_all.py       # 109 项：全部五层自测，零 Token
```

其中一条最值得单独说：**卡片里出现的每个金额，都必须来自接口返回
或它们的精确和**。这条断言还配了反向验证——往卡片里塞一个 `¥888.8`，
当场被揪出来。铁律 1（绝不估算价格）到这一层是机器在守，不是靠自觉。
