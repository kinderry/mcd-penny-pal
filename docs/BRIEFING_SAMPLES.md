> **状态：版本 A（软萌搭子版）已定稿，第三次调性打磨后定为「奶龙语气」。**
> 文末「引擎实跑」那一份由 `tools/run_briefing.py` 直接生成，不是手写的——
> 里面的每个数字都能追到某一次 `calculate-price` 调用。
>
> 下文三个版本共用同一套信息骨架，只有语气不同。保留 B / C 两版是为了留下
> **选题依据**：为什么在榜一榜二都做"精算师大表格"的情况下，我们选软萌搭子版。
>
> 数据全部取自 2026-10-16 账户真实返回：券包 6 张、积分可用 9.9 / 已过期 387.1、
> 门店券 3 张。

## 信息骨架（三版共有）

不管语气怎么变，信息顺序锁死，保证「结论先行」：

| 顺序 | 内容 | 不可省略 |
|---|---|---|
| 1 | 状态标签 | 是 |
| 2 | 一句话结论（今天最要紧的事） | 是 |
| 3 | 临期清单（券名 + 到期时间） | 是 |
| 4 | 建议动作（一句，不催单） | 是 |
| 5 | 口径与免责 | 是 |

调性只是这套骨架外面的一层皮。换皮不换骨。

## 版本 A｜软萌搭子版 ★ 主推

**定稿形态**（M2 接上之后，金额是真实计价的结果）：

```
【着急】哎呀哎呀！你有 2 张券券，今晚 23:59 就到期啦！

券包里有 6 张券券哦，今天就没了的是这 2 张（钱都按实时菜单算过，不是券面那个数）：

· 中薯条买一送一（省 ¥13.5）
· 王牌小食拼（省 ¥6.1）

这 2 张加起来能省 ¥19.6 哦。是拿实时菜单算过的，真的！

「王牌小食拼」小省要小小声跟你说哦：券面写着 ¥15.9，可是实际只能省 ¥6.1。券面那个数字是用券后的价，不是省下来的钱，不要被它骗到啦！

对啦对啦，这 3 张券券也在倒计时哦：明天「巧克力味厚松饼猪柳蛋套餐」、2 天后「人气麦旋风买一送一」、2 天后「巧克力味厚松饼猪柳蛋套餐」。

积分也要说一句哦：能用的只剩 9.9 了，已经过期掉 387.1 分。攒着不用，它是真的会没的哦。

要小省帮你算算今天这一单怎么点最省吗？给个预算，我来比。
```

**初稿形态**（M2 接入前，只有券面价，且语气更"设计腔"）——保留它是因为能看出两件事：
"核价"这一步换来了什么，以及语气从"用力"改成"松弛"之后读感差多少。

```
【着急】小省报到：你有 2 张券今晚 23:59 就到期了。

券包里一共 6 张，这 2 张今天就没了：

· 中薯条买一送一
· 王牌小食拼

券面标注分别是 ¥13.5、¥15.9——但能不能真把钱省下来，我得拿实时菜单
核过才算数，不给你报虚的。

...
```

初稿那句"不给你报虚的"是个**承诺**；定稿里它已经**兑现**了：
券面 ¥15.9 的「王牌小食拼」实测只省 ¥6.1，引擎主动把这个差额说破。
承诺谁都会写，兑现才是差异点。

**设计意图**

- 开口就着急，因为**这两张券确实今晚归零**，情绪是事实驱动的，不是装的。
  但语气是软的（"哎呀哎呀…啦"），不是喊的——**急是因为事，不是因为你**。
- 报数字的那一句刻意不加语气词（"这 2 张加起来能省 ¥19.6 哦"）：
  萌是让人愿意听，**钱的事必须说干净**。
- **「券面价 vs 实测省额」那一段是整个简报最值钱的地方。** 用户看着券面写 ¥15.9，
  以为省了 15.9；实际只有 6.1。不核价、不说破，这个简报就只是个复读机。
- 积分那段是**主动播报**，用户没问。这就是"搭子"和"工具"的分界。
- 最后是邀请不是催促。"给个预算"把决定权交回用户，绕开诱导消费的坑。

**为什么往软里调**：第一版"搭子版"虽然有人格，但句式偏紧、每句都在使劲
（破折号解释句、"不给你报虚的"反复出现、"提一句/顺带一提"这类过渡词），
读起来像**精心设计过的模板**而不是人在说话。第二版把过渡词和长解释句拆掉，
换成短句 + 少量语气词，**萌度上去了，可信度没降**——
因为所有金额锚点和口径断言一条都没动。

**为什么还要再往软里调（第三版 · 奶龙语气）**：第二版虽然软了，但句子还是"长句套软壳"——
一个句子里塞了三四个分句，语气词只是挂在尾巴上。奶龙那种语感的核心不是"加语气词"，
而是**句子真的短**：一句说完一件事，说完就断，还会重复强调自己。

这一版做了四件事：

| 手法 | 第二版 | 第三版 |
|---|---|---|
| 断句 | 一个句子套多个分句 | **一句话一件事**，逗号改句号/感叹号 |
| 重复 | 无 | "哎呀哎呀""对啦对啦""真的！" |
| 叠字 | 零星 | "券券""小小声""安心安心" |
| 语气词位置 | 只挂在句尾 | 句尾 + 小句之间（"…哦。是拿实时菜单算过的，真的！"） |

⚠️ **代价与守住的东西**：句子变短，但**口径关键词一个都没换**——
`未核到价` / `券面写着` / `用券后的价` / `加起来能省` / `在倒计时` / `就作废`
全部原地保留。它们既是"数字可信"的载体，也是 109 项自测的锚点。
所以这一版改完，**测试零改动、109 项全绿**。

## 版本 B｜顾问版

```
麦当劳优惠券资产简报 · 2026-10-16
账户：kinderry

【风险项｜T-0 到期】
  中薯条买一送一        用券价 ¥13.5    2026-10-16 23:59    建议优先使用
  王牌小食拼            用券价 ¥15.9    2026-10-16 23:59    建议优先使用

【关注项｜T-2 到期】
  人气麦旋风买一送一    用券价 ¥15.0    2026-10-18 23:59    本周内处理

【积分账户】
  可用 9.9 ｜ 累计 397 ｜ 已过期 387.1
  提示：已过期部分不可恢复。

【口径说明】
  1. 表中"用券价"为券面标注值。实际节省额须经 calculate-price 实时核验后给出。
  2. 本简报仅陈述账户事实，不含购买建议。
```

**设计意图**

- 表格化、分档、编号。像一份发给投资人的月报。
- 优点：信息密度最高，专业感强，适合当"证据"给评委看。
- 缺点：**没有人会截图转发这种东西**。而且榜一榜二已经站在这个位置上了。

## 版本 C｜极简播报版

```
2 张券今晚到期：中薯条买一送一、王牌小食拼。
后天还有 1 张：人气麦旋风买一送一。
积分可用 9.9（已过期 387.1）。
要算最省点法吗？
```

**设计意图**

- 四行，零情绪，像系统推送。
- 优点：不打扰，适合做成每日定时播报。
- 缺点：记不住、没有辨识度。用户不会因为它产生"这个搭子挺有意思"的感觉。

## 三版对比

| 维度 | A 软萌搭子版 | B 顾问版 | C 播报版 |
|---|---|---|---|
| 语感 | 熟人 + 小朋友 | 财务顾问 | 系统通知 |
| 首句 | 结论 + 情绪 | 标题 + 日期 | 干货直给 |
| 信息密度 | 中 | 高 | 低 |
| 有没有人转发 | **会** | 不会 | 不太会 |
| 长度 | 中 | 长 | 极短 |
| 主要风险 | 萌过头会腻 | 冷，没人记得 | 信息量不够 |

**榜单现实**：榜一 449★、榜二 342★，两个都是 B 那一挂（精算师、大表格）。我们继续做 B，就是在他们最强的维度上硬碰硬。

**所以主推 A。** 三个理由：

1. **差异化只能从语气里来。** 硬核算法大家都有——四路券池合并、真实计价、临期预警，榜一榜二都做了，而且做得不差。但"有人格、会主动找你"这件事，满榜 103 个项目里没人做。
2. **Star 是靠截图传出去的。** 这个比赛的记分板是 Star 数，而 Star 来自"这个看起来有意思"。B 那种表格截图发出去没人点开。
3. **人设不牺牲严谨。** A 里照样报了实时菜单算出来的金额、照样标了真实到期时间。情绪标签（【着急】/【得意】/【平常】/【空手】）是**按券状态计算出来的**，不是随机撒娇——它是可编程的，也是可验证的。

## 引擎实跑

下面这份**不是手写的**，是 `python tools/run_briefing.py` 从 `fixtures/raw/` 的真实返回直接生成的。
零 Token 就能复现，结果与联网时一致（fixtures 就是真实返回的原样落盘）。

```
【着急】哎呀哎呀！你有 2 张券券，今晚 23:59 就到期啦！

券包里有 6 张券券哦，今天就没了的是这 2 张（钱都按实时菜单算过，不是券面那个数）：

· 中薯条买一送一（省 ¥13.5）
· 王牌小食拼（省 ¥6.1）

这 2 张加起来能省 ¥19.6 哦。是拿实时菜单算过的，真的！

「王牌小食拼」小省要小小声跟你说哦：券面写着 ¥15.9，可是实际只能省 ¥6.1。券面那个数字是用券后的价，不是省下来的钱，不要被它骗到啦！

对啦对啦，这 3 张券券也在倒计时哦：明天「巧克力味厚松饼猪柳蛋套餐」、2 天后「人气麦旋风买一送一」、2 天后「巧克力味厚松饼猪柳蛋套餐」。

积分也要说一句哦：能用的只剩 9.9 了，已经过期掉 387.1 分。攒着不用，它是真的会没的哦。

要小省帮你算算今天这一单怎么点最省吗？给个预算，我来比。
```

对照最初手写的 A 版样例，两处差别，都是**引擎纠正了我**：

| 手写样例 | 引擎实跑 | 为什么改 |
|---|---|---|
| 提了 2 张今日到期券 | 也是 2 张 | 起初引擎报 **3 张**，因为它把「明天 10:29 到期」算成了今天 —— 修掉一个错位一天的 bug |
| 「后天（10-18）还有一张人气麦旋风」 | 「明天「巧克力松饼」、2 天后「麦旋风」、2 天后「巧克力松饼」」 | T-3 档有 3 张，只说"还有一张"用户没法行动，改成逐个点名 |

**引擎跑出来的真实发现**（都不是设计时想到的）：

1. **错位一天的 bug。** `timedelta.days` 把「相差 23.5 小时」算成 0 天，于是明天到期的券被报成"今天到期"。必须改用自然日差 `(deadline.date() - now.date()).days`。
2. **「免费脆薯饼」状态是「已领取」，但券包里没有它。** 可领池说领到了，券包不认。引擎一律以券包为唯一资产口径。
3. **领完券后，可领池那 7 张的 status 全变成「已领取」。** 简报不能再提示"还有 7 张可以领" —— 可领数只数真正"可领取"的。
4. **券的钥匙不在券包里。** 券包（`query-my-coupons`）只给标题和有效期，
   `couponId` / `couponCode` 只在门店券（`query-store-coupons`）里。
   没有这两个字段，`calculate-price` 认不出券、价格全返回 0。这条链路以前是黑的。
5. **门店券的返回会被"字段说明"污染。** 它的返回体**不带** `## Original Response`
   标记，前言里的 `## 字段说明`、`## 输出格式` 等文档标题会被当成券名，
   结果是真券一条没解析出来、4 条垃圾混进券池（券包总数从 6 虚报成 10）。

这五条都写进了对应模块的注释，并且有自测断言锁着
（`tools/test_parser.py` 14 项 / `test_briefing.py` 25 项 / `test_valuation.py` 31 项）。

## 省钱额是怎么算出来的

简报里那句"能省 ¥19.6"不是估的，链路是：

```
query-my-coupons    → 券包 6 张（**唯一带真实有效期**，但**没有** couponId）
query-store-coupons → couponId / couponCode / 券专属商品编码   ← 钥匙在这里
calculate-price     → 带上 couponId + couponCode 试算
                    → 返回 discount = 1350 分 = 这张券真实省 ¥13.5
```

三个必须记住的口径：

1. **`calculate-price` 的单位是「分」**，而菜单的 `currentPrice` 是**元字符串**。混用差 100 倍。
2. **券面价 ≠ 节省额。**「王牌小食拼」券面 ¥15.9、实省 ¥6.1。排序和播报一律以 `discount` 为准。
3. **能核价的券必须先落在门店券里。** 券包有 6 张，门店券只有 3 张——
   所以只有 3 张能核价。剩下 3 张（「人气麦旋风」「巧克力松饼」×2）
   引擎**明确说不出它值多少钱**，简报里也就不给它们标金额。

第 3 条正是铁律 3 的落点：**反查不到的，价值记 0 并标注"无法估价"，宁可少报，不可编造。**
如果简报里写"这 6 张券值 ¥19.6"，那是撒谎——只有 2 张核过价。
