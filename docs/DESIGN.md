# 麦小省 · 产品设计说明

> 麦当劳程序员创意开发大赛参赛作品 · 设计文档
> 状态：已实现（2026-10-16）· 自测 109 项全绿 · 零 Token 离线可复现

## 一句话定义

**麦小省**是一个住在你手机里的卡通省钱搭子。打开它，它会主动告诉你：今天有哪些券忘了领、哪张券明天过期、这一顿怎么点最省——然后帮你真的把单下掉，并把省下的钱记进账本。

## 为什么不做第 4 个"精算师"

截至 2026-10-16 09:00，榜前 3 分别是 449★ / 342★ / 308★，全是精算师人格：严肃、被动、输出大表格。

我们不硬碰这条线，而是**反过来做三个动作**：

| 头部在做 | 麦小省在做 |
|---|---|
| 被动：你问它才答 | **主动**：打开就播报今日省钱简报 |
| 冷：数字和表格 | **有人格**：券快过期它会着急，省到钱它会邀功 |
| 日志：输出一屏分析 | **卡片**：输出一张可截图分享的战报 |

代码硬实力（真实计价、四路券池合并、离线可复现）一样不少——只是把它包在一个愿意被人点 star 的壳里。

## 四个能力模块

### M1 券管家 · Catch

**核心：四路券池合并。** 少查一路，用户就少省钱。

| 券池 | 工具 |
|---|---|
| 麦麦省待领券 | `available-coupons` → `auto-bind-coupons` |
| 我账户已有券 | `query-my-coupons` |
| 当前门店专属券 | `query-store-coupons`（需先 `query-nearby-stores` 定位门店）|

产出：券包体检表 —— 每张券的名义面值 vs 可兑现价值（名义 ¥50 的券，可能只兑现得了 ¥12），以及**临期预警**（默认 T-3 天）。

### M2 比价官 · Calc

- `query-meals` 拉当前门店实时菜单（价格主数据源，绝不写死）
- `query-meal-detail` 查套餐组成与可替换项
- `calculate-price` 所有候选方案**逐个真实计价**，不复用历史价、不估算
- 支持三种约束：预算硬上限 / 热量上限（`list-nutrition-foods`）/ 仅限外送

产出：2–3 个候选方案 + 省在哪的归因。

### M3 下单员 · Order

`create-order` 直接下单返回支付链接；`query-order` / `order-list` 追踪；`cancel-order` 反悔。

## M4 记账本 · Ledger

从 `order-list` 还原真实消费：月度支出、客单价、高频单品。**整单退款不计入消费**。
叠加 `query-my-account`（积分余额）——积分是另一种有保质期的钱。

## 卡片 · Share

简报是"用起来"的，卡片是"截图发出去"的。这是 star 的主要来源，所以单独当一个模块做。

规格：1080×1440（3:4 竖版），单文件 HTML，形象图 base64 内联 —— 不依赖外部资源，
不需要装任何东西，双击就能开、就能截。

```
状态标签 → 一句话结论 → 今天能省 ¥19.6 → 按省得多排序的券清单
        → 积分状况 → 形象 + 仓库地址
```

三条卡片专属纪律（比简报更严，因为卡片是要被传播的）：

| 纪律 | 为什么 |
|---|---|
| 只讲能核到价的券 | 门店券里没有的券，卡片上一个数字都不给 |
| 部分可估时不说"今天能省" | 改说"这是已核价的 2 张"，并点明还有几张没核过 |
| 大数字只算最紧急那一组 | 把 today + soon 混算会出现"2 张今天到期"配"4 条清单"的错位 |

高度是**自适应**的（`min-height`），不是写死 1440。券多的时候内容会更长，
写死高度会把最后一行挤出画布 —— 这个坑实测踩过，自测里有断言守着。

## 合规红线（规则明令，逐条自查）

1. ❌ 不做麦当劳与其他品牌的价格/产品对比
2. ❌ 不带"薅垮商家""白嫖"调性，不做诱导消费
3. ✅ 所有金额必须来自 MCP 计价接口，宁可少报不可编造
4. ✅ 无法反查到原价的券，价值记 0 并在报告中标注
5. ✅ 不使用真实麦当劳商标图形做角色设计（红黄配色可，拱门标志不可）
6. ✅ 仓库内不出现任何真实 Token / 手机号 / 收货地址
